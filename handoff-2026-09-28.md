# UlpaQuiz Handoff — 2026-09-28

## Current project state
This repo is the UlpaQuiz app, a React + TypeScript + Firebase-hosted quiz app for students and managers. The app is already wired to Firebase Auth and Firestore, with a mobile-friendly flow and a custom admin experience.

The app is currently in a stable-but-guarded state after several fixes:

- Manager quiz participation is supported for verified managers.
- Existing approved Gmail users can be promoted to manager status from the admin panel.
- Manual manager creation remains available.
- The student registration bug with `undefined` invitation codes was fixed by omitting blank invitation values instead of writing them as `undefined`.
- The admin polling loop was reduced to avoid Firestore rate throttling.
- Manager transaction retries are limited to prevent repeated quota hits.

## What has been fixed today
### 1) Student registration fix
Root cause:
- Firestore rejected writes when `invitationCode` was explicitly set to `undefined`.

Fix:
- Omit the field entirely when the invitation code is blank.
- This protects registration for users who do not have an invitation code.

### 2) Manager participation and promotion flow
Work completed:
- Managers can participate in the daily quiz through a stable manager-only profile.
- Manager-only participation is excluded from student lists and leaderboard/prize reporting.
- Existing eligible Gmail users can be promoted from the admin panel.
- The manager action now has visible loading/error handling.

### 3) Firestore throttling / quota issue
We observed repeated Firestore 429 / `resource-exhausted` errors and saw that the app was doing too many reads in a short time.

Fixes applied:
- Removed the aggressive 5-second admin polling loop.
- Kept a manual refresh and refresh-on-open behavior instead of continuous polling.
- Capped manager transaction retries.

Current understanding:
- This did not fully eliminate the quota problem by itself; it reduced the chance of hitting the limit again.
- The app appears to be subject to Firestore read quota exhaustion or rate throttling on the project.
- The actual usage must be checked in the Firebase Console to confirm whether this is daily quota exhaustion or short-term throttling.

## Current blocker
The main remaining issue is Firestore rate limiting / quota usage.

### Evidence
- Multiple `429 Too Many Requests` and `resource-exhausted` errors were showing in app logs.
- The previous aggressive polling triggered repeated reads.
- The CLI quota commands using `gcloud` were not available in the installed Google Cloud SDK.

### What we found about the CLI
This environment’s SDK does not support the quota query commands we tried.

Commands attempted:
- `gcloud services quota list`
- `gcloud beta services quota list`
- `gcloud monitoring time-series list`

Result:
- The installed Google Cloud SDK is missing the needed command groups or component support.
- The `beta` component installation was blocked by permissions in the default install location.
- `gcloud monitoring time-series list` is not a valid command for this installed SDK.

Because the quota CLI is not available here, the correct inspection path is:

- Firebase Console
- Firestore Database
- Usage / quota section

This is the actual place to verify Firestore read volume and whether the project is hitting its free-tier or quota limits.

## Firebase account / project notes
Because we may need to switch accounts or work from a different Google account, the safest workflow is to keep the project and Firebase config separate from the local machine state.

### Recommended account switch flow
From PowerShell:

```powershell
firebase logout
firebase login --no-localhost
firebase projects:list
firebase use <project-id>
```

If the user has multiple Firebase accounts and wants to keep both alive:

```powershell
firebase login --reauth
firebase use --add
```

Then select the correct project after login.

### If Firebase CLI is tied to the wrong account
Use:

```powershell
firebase logout
firebase login --no-localhost
```

Then confirm the active project is the correct one:

```powershell
firebase use <project-id>
```

### When using gcloud as well
On Windows, use the SDK executable directly if needed:

```powershell
"C:\Program Files (x86)\Google\Cloud SDK\google-cloud-sdk\bin\gcloud.cmd" --version
```

This environment currently cannot reliably use the quota commands due to missing components and install permissions. That is a local CLI limitation, not necessarily a project issue.
